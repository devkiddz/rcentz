## Better Auth 1.7 corrections

The Account model now uses:

```prisma
issuer    String
accountId String

@@unique([issuer, accountId])
```

Better Auth 1.7.2's installed TypeScript declarations in the validated Rcentz checkout
currently reject `account.identityStrategy`, despite the current Better Auth documentation
describing that option. Rcentz therefore omits the option rather than suppressing or casting
the type error. Better Auth documents omission as a v1.7 compatibility mode.

`User.name` is required to match Better Auth's core user contract.

`role` and `status` are declared as Better Auth additional fields with `input: false`, so clients cannot grant themselves privileged roles or change their own account status through auth input.

The browser auth client no longer hardcodes localhost; same-origin `/api/auth` is used automatically.

## Project architecture correction

`ClientProject` and `PortfolioProject` are replaced by one canonical `Project`.

Public portfolio presentation is represented by optional `PortfolioProfile`.

This allows a real project such as AJ Logik to power:

- internal project management
- client-visible tracking
- public portfolio presentation
- public project updates
- project analytics
- SEO
- comments/reactions
- technologies/media

without duplicating project identity.

## Important integrity rule

Prisma cannot express every cross-model domain invariant elegantly.

The server/business layer must validate that:

- a phase, milestone, feature, or task referenced by a project operation belongs to the same project
- a feature dependency cannot reference itself
- both sides of a feature dependency belong to the same project
- Comment and Reaction have exactly one target (`postId` or `projectId`)
- MediaAsset has exactly one owner relation
- SeoMetadata has exactly one owner relation
- a contextual Conversation points to the entity matching its conversation type
- ServiceRequest → Quote → Project client ownership remains consistent

These are authorization/business validation responsibilities, not UI responsibilities.

## Migration approach

Do not delete or reset a database automatically.

Because this is still pre-seed and the project/portfolio tables appear not to contain canonical real portfolio data yet, there are two valid approaches:

1. **Clean development reset** — preferred if the database contains only disposable test data.
2. **Normal migration** — required if there is data you want to preserve.

Choose deliberately before running a destructive Prisma command.

## UI direction

The prepared UI foundation does not choose an animation library or global motion behavior.

It establishes:

- monochrome semantic tokens
- Rcentz bounded canvas/content widths
- grid and grid-fade background utilities
- Geist Sans + Geist Mono currently retained
- no global animation

This preserves the Vercel + Prisma inspiration while keeping the Rcentz grid identity. Motion can be introduced per component later, with `prefers-reduced-motion` considered.
